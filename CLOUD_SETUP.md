# CreatorOS cloud backup (optional)
Requires a NEW dedicated Supabase project. No database was provisioned or configured by this source-code change. Run supabase/setup.sql once in that project's SQL editor, enable email/password authentication, disable public signup for private single-user use after creating and confirming the owner's account, and test RLS with two distinct users before enabling real data. Never use a service-role or secret key in the browser.

In CreatorOS: unlock local vault, open Cloud sync, enter the project's 20-character ref and publishable key (sb_publishable_...), sign in with your confirmed Supabase email/password, and choose an independent backup encryption passphrase. Keep it private. Use upload on source device and restore on target device. Explicit confirmations prevent silent overwrite; revision-filtered PATCH protects concurrent writes after the cloud row is read. This is manual snapshot transfer, not auto-sync or merge. Cloud payload is AES-GCM encrypted with a fresh salt and IV; local media binaries are excluded. Existing local media is retained on restore. Export local JSON before restoring; plaintext exports must be stored privately. No secrets or account credentials are committed.

Acceptance checks required after provisioning: successful/invalid auth, anonymous and cross-user denial, backup upload, wrong passphrase rejection, second-device restore, stale revision conflict, offline handling, local media retention. Live YouTube/Instagram and AI integrations are separate and not implemented here.
